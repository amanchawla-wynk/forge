# Open-Source PRD Project Architecture Audit

Current through **2026-09-25**. Repository behavior was inspected at the pinned commits below; README claims were used only when corroborated by executable source or prompt files. All sources were accessed 2026-09-25.

## How the projects represent and run PRD review

### Takeaway

The four projects represent four materially different systems: a sequential specialist critique pipeline (`multi-agent-prd-reviewer`), a one-prompt weighted review rubric (`claude-requirements-reviewer`), a file-orchestrated creation/review/revision pipeline (`prd-agents-framework`), and a section-by-section authoring interview with hybrid validation (`NatPRD`) ([multi-agent orchestrator](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/orchestrator.py#L19-L109); [Claude reviewer skill](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/SKILL.md#L31-L258); [framework pipeline](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/skills/create-prd/SKILL.md#L81-L181); [NatPRD workflow](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L250-L326)). Only `prd-agents-framework` has a durable, explicit chain from questions and source research through review findings to adjudicated revision tickets, but none implements Forge's exact **Rubric -> verified Evidence -> deterministic Evaluation -> scored Gap -> one dynamic Question** chain ([framework Q&A](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-writer.md#L140-L168); [framework dispositions](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L186-L218); [Forge remediation](../../docs/SCORING_THEORY.md#remediation)).

#### Project 1: `multi-agent-prd-reviewer`

- The pipeline is strictly sequential: keyword validation, technical critique, UX critique, legal critique, then a summary. The UX call receives the technical critique; the legal call receives both prior critiques, creating context accumulation and ordering effects rather than independent specialist votes ([`orchestrator.py`](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/orchestrator.py#L52-L87)).
- The only numeric score is section completeness. A section is `found` when any configured substring occurs anywhere in lowercased PRD text; the score is the sum of severity weights divided by the required-section maximum ([`validator_agent.py`](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/agents/validator_agent.py#L56-L100)).
- There is a concrete scoring defect: optional sections add to `total_score` when found but add nothing to `max_score`, so documents containing optional Dependencies or Timeline keywords can exceed 100 ([`validator_agent.py`](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/agents/validator_agent.py#L74-L85); [optional template rows](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/templates/prd_template.yaml#L142-L162)).
- Substring matching is highly gameable: `build` can satisfy Executive Summary, `phase` can satisfy Scope and Timeline, `?` can satisfy Open Questions, and generic priority words can satisfy Out of Scope ([template keywords](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/templates/prd_template.yaml#L7-L24); [Open Questions and Out of Scope](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/templates/prd_template.yaml#L103-L176)).
- Specialist prompts contain useful domain coverage: assumptions, scalability, failure modes, operational support, user journey/state completeness, accessibility, privacy, payment regulation, and audit trails. Findings are requested to name impact, action, and relevant PRD section ([technical prompt](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/prompts/skeptic_system.txt#L16-L68); [UX prompt](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/prompts/ux_system.txt#L16-L76); [legal prompt](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/prompts/legal_system.txt#L16-L77)).
- Prompt personas are narrow and potentially over-applied: the technical persona assumes high-scale payment/ticketing expertise and the legal persona emphasizes UK/EU digital consumer law, regardless of PRD domain or geography ([technical persona](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/prompts/skeptic_system.txt#L1-L7); [legal persona](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/prompts/legal_system.txt#L1-L7)).
- Slack is a useful review-delivery pattern: users can paste text or upload Markdown/PDF/DOCX; output preserves an at-a-glance status, completeness, counts, each critique, and model/token/timestamp metadata. It is not interactive after review ([`slack_bot.py`](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/slack_bot.py#L144-L293); [`slack_formatter.py`](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/utils/slack_formatter.py#L27-L144)).
- The architecture directly uses the Anthropic SDK and requires `ANTHROPIC_API_KEY`; model is hard-coded as `claude-sonnet-4-6` in all three model agents ([skeptic](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/agents/skeptic_agent.py#L20-L37); [UX](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/agents/ux_agent.py#L21-L37); [legal](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/agents/legal_agent.py#L21-L37)).

#### Project 2: `claude-requirements-reviewer`

- All behavior resides in one prompt. It tells the model to act simultaneously as senior PM, engineering manager, and reviewer, assign weighted points, produce exact-text evidence, and recommend improvements ([`SKILL.md`](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/SKILL.md#L11-L27); [scoring](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/SKILL.md#L131-L164)).
- Review dimensions and weights are embedded in the same prompt visible to the scoring model. This makes the score a model judgment rather than a verified derivation and permits the model's prose interpretation to determine both findings and points ([`SKILL.md`](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/SKILL.md#L31-L145)).
- The finding shape is directionally useful: exact evidence, impact, recommendation, contradiction references, hidden assumptions, explicit in/out/ambiguous scope, and missing acceptance criteria are separated in the report ([`SKILL.md`](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/SKILL.md#L193-L258)).
- The example output does not follow the prompt's full schema: it omits dimension scores and several required sections, demonstrating that a prose-only output contract is not self-enforcing ([sample review](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/examples/sample-review-bad.md#L1-L67); [required format](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/SKILL.md#L168-L258)).
- There is no source implementation for question selection, answer retention, revision, quote validation, stable criterion IDs, file output, or run provenance beyond whatever the host conversation happens to retain ([repository tree](https://github.com/amodiahs/claude-requirements-reviewer/tree/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca)).

#### Project 3: `prd-agents-framework`

- The top-level workflow is a human-gated pipeline: scope clarification -> research -> research approval -> writer questions/draft -> draft approval -> matrix review -> senior-PM adjudication -> targeted revision -> re-review, capped at three normal revision cycles ([create skill](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/skills/create-prd/SKILL.md#L81-L181); [revision loop](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/skills/create-prd/SKILL.md#L509-L514)).
- Question flow is contextual before drafting. Scope questions include a best guess; research records unresolved `ASK:role` ambiguities; the writer asks all remaining scope, UX, rule, and tradeoff questions and recommends answers based on research ([create skill](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/skills/create-prd/SKILL.md#L81-L97); [writer](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-writer.md#L112-L138)).
- Answers are retained unusually well: `_artifacts/{initiative}-writer-qa.json` stores exact question, resolution method, recommended answer, exact user answer, resolved value, and whether it is a shared-requirement candidate ([writer Q&A schema](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-writer.md#L140-L168)).
- Review begins by exhaustively extracting FRs, ACs, endpoints, screens/states, entities, edge cases, and out-of-scope items, then scaffolds fixed matrices. Documents below 20 extracted items use one reviewer; larger ones dispatch five specialist passes ([reviewer](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L163-L193); [matrix ownership](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L562-L572)).
- It avoids one common multi-agent failure by assigning each review axis a single owner: the smell agent alone scans per-item language/separation smells, while structure and requirements agents are forbidden to duplicate that work ([reviewer](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L401-L415)).
- The final reviewer verifies that no `[PENDING]` cells remain, runs deterministic lint, spot-checks model PASS cells against source material, performs cross-matrix analysis, and derives the binary verdict from FAIL count ([reviewer](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L711-L749); [verdict](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L766-L811)).
- The senior-PM layer is a notable review pattern. It treats each FAIL as a claim, collapses duplicate cells to root causes, separately judges evidence and impact, rejects overreach/variance/no-impact/harmful fixes, decides grounded product questions, and escalates only those not answerable from evidence ([senior PM](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L12-L21); [evidence axis](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L89-L147); [decision search](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L167-L184)).
- Senior-PM output is structured around four dispositions: `fix-technical`, `fix-product`, `reject`, `escalate`. Surviving findings become location-specific tickets with decision, rationale, and evidence; users can veto any disposition before revision ([senior PM](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L186-L218); [user gate](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/skills/create-prd/SKILL.md#L429-L492)).
- Revision is deliberately delta-oriented: writer consumes adjudicated tickets rather than raw FAILs, writes a new versioned PRD instead of overwriting, records applied ticket IDs, and the next senior-PM pass verifies each as applied/partial/not-applied without reopening settled dispositions ([writer revision](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-writer.md#L170-L198); [senior-PM delta mode](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L35-L60)).
- Provenance is broad but uneven. Handoff shapes, counts, mode, status, next agent, and disposition consistency are deterministically validated; the review prompts require exact quotes and code/doc checks, but no generic `locate_quote` equivalent verifies every model-cited finding ([handoff validator](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/scripts/validate-handoff.py#L36-L71); [reviewer evidence instructions](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L584-L608)).
- Its own evaluation document explicitly measures reviewer noise: the same reviewer returned 12, 14, 24, and 24 FAIL cells on one frozen PRD. It recommends mechanism checks, root-cause deflation, blind judges only as tiebreakers, and human choice as final metric ([`EVAL.md`](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L1-L15); [full eval](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L46-L86)).

#### Project 4: `NatPRD`

- NatPRD is primarily a PRD authoring system, not a gap-remediation reviewer. It first asks 16 intake questions, uses answers to select optional sections, then walks through every core section in order and validates before progressing ([`SKILL.md`](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L250-L298); [intake](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/interview-questions.md#L9-L185)).
- The interaction design is concrete: one question at a time; button UI for 2-4 exclusive choices; free text for open questions; multi-select for grouped compliance signals. This is a useful cognitive-load pattern, although the full interview is long ([`SKILL.md`](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L43-L63); [interview header](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/interview-questions.md#L1-L5)).
- Static questions become context-sensitive through conditional branches. Payments/PII trigger regulation identification; team/vendor answers trigger dependencies/stakeholders; requirements prompt explicit checks for failure, admin, permissions, abandonment, and onboarding ([interview](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/interview-questions.md#L40-L96); [gap checks](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/interview-questions.md#L321-L346)).
- Anti-hallucination policy is strong and user-visible: unknown values become typed `[TBD]` markers; metrics, owners, dates, links, evidence, and event names may not be invented; TBDs score as missing ([`SKILL.md`](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L67-L102)).
- External evidence has an explicit consent/provenance flow: use only user-named paths/URLs or confirmed registry URLs, show the exact fact before writing, annotate source and retrieval date, and collect references. Autonomous search and source paraphrase are prohibited ([`SKILL.md`](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L106-L176)).
- The deterministic validator covers structural checks while explicitly leaving semantic judgments to the model. Unknown/TBD content receives the same deduction as missing but is reported as a warning, except hard status gates ([`validate.py`](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/scripts/validate.py#L10-L25); [field handling](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/scripts/validate.py#L129-L179)).
- Its score measures conformity to one opinionated document template, not just implementation readiness. For example, missing a design link, at least one considered alternative, company OKR alignment, FAQ content, named review dates, or event naming all reduce or block the result ([validation rubric](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/validation-rules.md#L10-L24); [section rules](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/section-rules.md#L51-L58)).
- Ordinary author answers are not stored separately from the generated PRD. The source defines only in-place section update, automatic version/date changes, and revalidation; it does not define an immutable answer ledger or new-copy revision strategy ([update mode](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L314-L326); [versioning](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L211-L236)).

### Inferences

- `prd-agents-framework` is the closest architectural benchmark for review-to-revision governance, while NatPRD is the strongest interview/anti-hallucination benchmark. Neither is a suitable scoring architecture to copy wholesale because the former gives models broad PASS/FAIL authority and the latter mixes deterministic checks with model-assigned semantic deductions ([reviewer verdict](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L799-L811); [NatPRD validation split](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/validation-rules.md#L85-L111)).
- The strongest provenance pattern is layered: source facts and questions have durable IDs, user answers remain exact, review assertions are separately adjudicated, and revision tickets retain evidence. Forge already has stricter quote verification; the external opportunity is richer review-decision lineage, not weaker model-authored scoring ([framework Q&A](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-writer.md#L140-L168); [senior-PM tickets](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L206-L218)).
- Repeated full-document specialist review produces breadth but creates cost, correlated findings, and ordering effects. The multi-agent pipeline demonstrates cumulative context growth; the PRD agents framework's own measured 2x review variance shows that more agent calls do not by themselves create reliable evaluation ([multi-agent prompts](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/agents/legal_agent.py#L100-L123); [`EVAL.md`](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L7-L15)).

### Gaps

- None of the repositories publishes human-labeled precision/recall, false-ready rates, or criterion agreement for its primary review output. `prd-agents-framework` publishes a methodology and one worked example, but not a reusable labeled corpus in this repository ([`EVAL.md`](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L119-L181)).
- `claude-requirements-reviewer` has no license file at the inspected revision, despite its README's MIT statement; legal reuse should be confirmed before borrowing any substantial text ([README](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/README.md#L290-L292); [tree](https://github.com/amodiahs/claude-requirements-reviewer/tree/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca)).
- No repository provides enough runtime transcripts to verify that host models consistently obey every prompt-level gate, particularly exact one-at-a-time interviewing and every required artifact write. The audit therefore distinguishes prompt-prescribed behavior from mechanically enforced behavior ([NatPRD skill workflow](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L250-L326); [framework validator boundary](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/scripts/validate-handoff.py#L24-L35)).

## How these systems differ from Forge's intended flow

### Takeaway

Forge's differentiator is not simply a rubric or interview. It is a trust boundary: the model extracts or selects within a closed set, Python verifies source evidence and computes outcomes, gaps are deterministic projections of the scored audit, one question targets one missing field or one uncovered edge-case cell, answers retain separate provenance, and unchanged documents are not repeatedly re-extracted ([Forge scoring theory](../../docs/SCORING_THEORY.md#extraction-before-judgment); [Forge remediation](../../docs/SCORING_THEORY.md#remediation); [Forge architecture](../../docs/ARCHITECTURE.md#trust-boundaries)). All four external projects violate at least one central link in that chain, as detailed in the source comparison below.

| Repeated-document cost | Forge performs exhaustive initial extraction, answer-only criterion deltas at checkpoints, and a final full assessment only after materialization ([Forge scoring theory](../../docs/SCORING_THEORY.md#remediation)) | Multi-agent sends the full document three times; framework specialists and assembly re-read it; NatPRD revalidates after updates without a verified baseline/delta merge ([multi-agent agents](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/orchestrator.py#L58-L80); [framework re-entry](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L670-L682); [NatPRD update](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L314-L326)) |

#### Important conceptual differences

- Forge is advisory and explicitly does not decide whether the product strategy is correct. `prd-agents-framework` adds a senior-PM product challenge that decides product questions where possible, while both one-shot reviewers use readiness/approval language more strongly than Forge intends ([Forge product](../../docs/PRODUCT.md#purpose); [framework senior PM](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L149-L165); [multi-agent status](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/orchestrator.py#L126-L143)).
- Forge separates readiness scoring from advisory deep review. `prd-agents-framework` mixes conformance, factual verification, smells, readability, product judgment, and revision governance in one pipeline, although it correctly excludes readability notes and SR drift from the binary verdict ([Forge product](../../docs/PRODUCT.md#purpose); [framework reviewer](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L751-L764)).
- Forge's question flow starts after evidence-backed evaluation and is prioritized by failed gates, criterion weight, affected consumers, and stable ID. NatPRD's flow starts before a document exists and follows section order; the framework's flow starts from initiative ambiguity/research and later surfaces a batch of escalations at a gate ([Forge remediation ordering](../../docs/SCORING_THEORY.md#remediation); [NatPRD workflow](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L250-L298); [framework Gate 3](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/skills/create-prd/SKILL.md#L429-L490)).
- Forge's question text remains rubric-authored even when contextualized. The external projects permit unconstrained model-written questions, which can be more fluent but cannot guarantee stable semantics, field targeting, or score isolation ([Forge architecture](../../docs/ARCHITECTURE.md#mcp-tool-direction); [NatPRD probes](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/interview-questions.md#L222-L318)).

### Inferences

- Forge should compare itself against the external systems as separate benchmarks: NatPRD for author usability, `prd-agents-framework` for revision governance and review noise handling, `multi-agent-prd-reviewer` for specialist presentation breadth, and `claude-requirements-reviewer` as a minimal one-prompt baseline. Treating any one project as the architectural competitor would obscure the strengths of the others ([NatPRD interaction](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L43-L63); [framework evaluation](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L16-L86); [multi-agent Slack format](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/utils/slack_formatter.py#L27-L144)).
- Forge's evidence boundary is materially stronger than all four projects. The most valuable borrowing opportunities are therefore above and below scoring: richer review UX, structured disposition governance, immutable answer/revision lineage, and evaluation methodology. Borrowing any model-assigned score or unverified specialist verdict would erase Forge's principal advantage ([Forge decision D-005](../../docs/DECISIONS.md#d-005-extraction-evidence-then-deterministic-scoring); [framework noise finding](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L7-L15)).

### Gaps

- The repositories do not expose comparable end-to-end token and latency measurements for the same PRD. `multi-agent-prd-reviewer` records token counts but no corpus benchmark; `prd-agents-framework` says token counts are unavailable in Claude Code and records timing/model profiles instead ([multi-agent metadata](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/orchestrator.py#L97-L106); [framework logging note](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/skills/create-prd/SKILL.md#L562-L562)).
- The projects do not define a shared readiness construct, so their numeric or binary outputs cannot be compared directly with Forge's bands without a common blinded corpus and human labels ([Claude score interpretation](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/SKILL.md#L149-L164); [NatPRD bands](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/validation-rules.md#L28-L35); [framework verdict](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L799-L803)).

## What Forge should borrow, benchmark, or reject

### Takeaway

Borrow interaction and governance mechanisms, benchmark breadth and usability, and reject scoring/evidence shortcuts. The highest-value near-term ideas are a root-cause/disposition view over verified deep-review findings, stronger Q&A/revision lineage in user-facing audit output, and benchmark fixtures for contextual interview quality and reviewer noise ([framework root-cause/disposition flow](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L95-L218); [framework Q&A lineage](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-writer.md#L140-L198); [framework noise methodology](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L7-L44)).

#### Borrow

1. **Root-cause collapse before action.** Add a presentation/adjudication step that groups several verified findings or failed cells when one author decision resolves all of them. Preserve every original finding ID and quote, but show one resolution unit and its fan-out. This borrows the senior-PM deflation mechanism without giving a model authority to decide evidence or scoring ([senior PM collapse](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L95-L108)).
2. **Explicit finding dispositions.** For each advisory deep-review finding, support an auditable user-approved disposition such as `accept_for_revision`, `reject_not_real`, `reject_out_of_scope`, `defer`, or `needs_owner_decision`, with rationale and retained evidence. The external four-way disposition and veto gate are strong governance patterns, but Forge should keep the final choice with the user rather than an autonomous senior-PM model ([dispositions](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L186-L204); [veto gate](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/skills/create-prd/SKILL.md#L482-L492)).
3. **Richer answer audit records.** Forge already binds answers to criteria/cells; expose a user-readable Q&A ledger with exact question, base question, selected context anchor, exact answer, resolved field/cell, recommendation if any, timestamp, checkpoint, and revision edit ID. The framework's exact `question`/`recommendedAnswer`/`userAnswer`/`resolvedValue` record is a useful minimum ([writer Q&A schema](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-writer.md#L146-L165)).
4. **Revision ticket verification statuses.** After Forge writes and reassesses a new copy, report each approved edit as applied, partially applied, not applied, or contradicted, rather than relying only on aggregate score movement. This maps cleanly to Forge's existing per-edit plan and final assessment ([framework delta verification](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L52-L60)).
5. **Progressive interaction controls.** In the dashboard, use clickable options only for genuinely closed choices and free text for author decisions; retain one question per turn. NatPRD's 2-4-option rule and “Other” escape are specific and usable ([NatPRD choice UI](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L43-L63)).
6. **Visible unknowns without hallucination.** When materializing revisions, preserve unresolved facts as explicit owner-bound unresolved items rather than generating plausible content. NatPRD's typed TBD policy is a good UX pattern, while Forge should continue treating such values as absent evidence ([NatPRD anti-hallucination](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L67-L102)).
7. **Source-consent preview for imported facts.** If Forge later supports enriching revisions from user-supplied external sources, preview exact quotations and destinations before insertion, mirroring NatPRD's verify-before-write interaction while retaining Forge's own mechanical quote verification ([NatPRD verify-before-write](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L135-L163)).
8. **Role-oriented report navigation.** The Slack formatter's at-a-glance summary followed by separate technical/UX/legal sections is easy to scan. Forge should preserve deterministic consumer grouping and consider collapsible dashboard sections or filters, not specialist-generated prose ([Slack formatter](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/utils/slack_formatter.py#L27-L144)).
9. **One-owner-per-review-axis discipline.** When Forge adds detectors or advisory classifications, document which component owns each judgment and prevent duplicate detectors from emitting the same issue class. The framework's single-owner smell matrix is a useful maintenance pattern ([reviewer ownership rule](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L401-L415)).
10. **Artifact/schema invariants.** Extend deterministic validation around review/revision artifacts: count/list agreement, legal transitions, required keys, and next-action consistency. Forge already does much of this in domain state; the external handoff validator demonstrates the value of making every cross-agent contract executable ([`validate-handoff.py`](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/scripts/validate-handoff.py#L36-L71)).

#### Benchmark

1. **Question usefulness against NatPRD.** On the same incomplete PRDs, compare author-rated relevance, answerability, cognitive load, number of questions to close material gaps, and unsupported assumptions. NatPRD is a strong static/conditional interview baseline because it asks one question at a time and includes explicit gap probes ([NatPRD interview](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/interview-questions.md#L1-L5); [gap checks](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/interview-questions.md#L337-L346)).
2. **Finding precision and duplicate rate against `prd-agents-framework`.** Compare Forge deep-review findings with raw matrix FAILs and post-senior-PM root causes on blinded documents. Measure human-confirmed precision, blocker recall, duplicate/root-cause ratio, and harmful-fix rate rather than only count ([framework deflation](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L95-L147); [`EVAL.md`](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L24-L44)).
3. **Test/retest noise.** Re-run each reviewer on frozen inputs at least three times and report finding overlap, distinct root causes, score/band movement, and question stability. The framework's observed 12-24 FAIL range establishes why one-shot counts are insufficient ([`EVAL.md`](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L7-L15)).
4. **Role coverage against multi-agent prompts.** Use the technical/UX/legal focus lists as coverage hypotheses and regression prompts, not labels. Verify whether Forge's rubric/deep review catches the same real downstream blockers with evidence and fewer unsupported findings ([technical prompt](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/prompts/skeptic_system.txt#L16-L68); [UX prompt](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/prompts/ux_system.txt#L16-L76); [legal prompt](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/prompts/legal_system.txt#L16-L77)).
5. **Minimal-prompt baseline.** Use `claude-requirements-reviewer` as a cheap baseline in blinded comparisons: one call, visible weights, free-form evidence. Forge should demonstrate better quote validity, score determinism, question relevance, and revision traceability, not merely more output ([`SKILL.md`](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/SKILL.md#L131-L258)).
6. **Revision effectiveness.** Compare raw-review-driven revisions, adjudicated-ticket revisions, and Forge's approved-answer revision plans on introduced defects, unresolved findings, re-litigation, author edit acceptance, and final artifact quality. The framework's worked example reports fewer but nonzero new defects under ticket-based revision, making it a useful hypothesis rather than proof ([`EVAL.md`](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L161-L177)).
7. **Summary fidelity.** For every system, mechanically test whether headline status, counts, top findings, and next action can be reconstructed from the detailed audit without model interpretation. Multi-agent's summary ignores specialist findings, while Forge intends a deterministic projection ([multi-agent summary](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/orchestrator.py#L111-L155)).

#### Reject

1. **Model-assigned numeric scores.** Reject the Claude reviewer pattern and NatPRD's model-semantic score completion. A model may extract/classify within constrained schemas, but weights and aggregation must stay outside its context and authority ([Claude scoring](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/SKILL.md#L131-L145); [NatPRD split](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/validation-rules.md#L85-L111)).
2. **Keyword-presence completeness.** Reject global substring matching and severity arithmetic. It is vulnerable to unrelated mentions, placeholders, optional-section denominator bugs, and padding ([multi-agent validator](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/agents/validator_agent.py#L56-L100); [template keywords](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/templates/prd_template.yaml#L7-L183)).
3. **Unverified free-text specialist findings as score input.** Specialist lenses can suggest coverage and presentation, but their prose should not affect bands until converted to versioned fields or validated advisory detectors with verified quotes ([multi-agent critique storage](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/orchestrator.py#L89-L107)).
4. **Sequential critique chaining.** Reject passing one specialist's unconstrained prose to later specialists. It increases token use and creates anchoring/correlation without establishing truth ([UX prompt construction](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/agents/ux_agent.py#L89-L108); [legal prompt construction](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/agents/legal_agent.py#L100-L123)).
5. **Zero-FAIL approval semantics.** Reject `READY means zero model FAILs` as a Forge band rule: model review cells are noisy, some findings are overreach, and Forge is advisory rather than an approval gate ([framework philosophy](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-reviewer.md#L12-L25); [framework noise](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L7-L15)).
6. **Autonomous product decisions from implementation evidence.** Reject the senior-PM agent's authority to decide business behavior from code, sibling PRDs, or “named industry practice.” Forge may surface the evidence and decision required, but product intent remains with the author ([senior-PM decision hierarchy](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L167-L184)).
7. **Static exhaustive interview as default remediation.** Reject asking every template question regardless of what verified evidence already satisfies. Use NatPRD's probes as rubric-design and edge-case-taxonomy inputs, while Forge continues to ask only the highest-impact unresolved field/cell ([NatPRD full workflow](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L250-L298)).
8. **In-place revision without answer provenance.** Reject editing the original while merely bumping an internal version string. Forge should preserve source hash, explicit approvals, new-copy semantics, and final reassessment ([NatPRD update/version rules](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L211-L236)).
9. **Provider SDK/API-key coupling in the MCP/core path.** Reject the multi-agent reviewer's direct Anthropic dependency and hard-coded model. It conflicts with Forge's client-borrowed model and portable fallback boundary ([skeptic agent](https://github.com/dimospapadopoulos/multi-agent-prd-reviewer/blob/c0a076ddc07ea5bc4b1fc851f708a05de10b19d7/agents/skeptic_agent.py#L20-L37)).
10. **Copying rubric/prompt text from unclear licensing.** Do not copy substantial material from `claude-requirements-reviewer` unless its missing license file is resolved; independently re-express any generally useful review concepts ([README license claim](https://github.com/amodiahs/claude-requirements-reviewer/blob/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca/README.md#L290-L292); [repository tree](https://github.com/amodiahs/claude-requirements-reviewer/tree/6e5f4d05ac4cf80a98bb9d25a4d48097c1e820ca)).

### Inferences

- The highest-leverage Forge improvement is a **verified finding decision ledger**, not another specialist agent. It can combine Forge's quote-verified deep-review findings with the framework's root-cause/disposition/ticket lineage while keeping user authority and score isolation ([framework decision sheet](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/agents/prd-senior-pm.md#L224-L323)).
- Forge should make “mechanism metrics” first-class in evaluations: exact-answer retention, no full-document resend during ordinary question turns, no unsupported quote accepted, no rejected finding re-litigated, and every approved edit verified in the final artifact. `prd-agents-framework` correctly argues that these are less sampling-sensitive than raw finding counts ([`EVAL.md`](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L35-L45)).
- NatPRD's strength is pre-document discovery, whereas Forge's strength is post-document evidence-grounded remediation. A future “authoring mode” should remain a separate product mode rather than making the assessment loop inherit a 12-section static interview ([NatPRD generate workflow](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/SKILL.md#L252-L298)).

### Gaps

- Before adding a Forge finding-disposition layer, user research is needed on whether authors want to adjudicate every finding or only root-cause groups; the repositories demonstrate mechanisms but provide no usability study ([framework Gate 3](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/skills/create-prd/SKILL.md#L429-L490)).
- Benchmarking cannot establish scoring validity without representative PRDs and independent human labels. The projects' own outputs can serve as comparator systems, not ground truth ([`prd-agents-framework` evaluation guidance](https://github.com/vshidlovsky/prd-agents-framework/blob/36504811641d79c50a4caa1f76d223fc4caea797/EVAL.md#L46-L86)).
- It remains unknown whether NatPRD's very long prescribed interview improves completion enough to justify user burden; no completion, abandonment, or time-on-task data is published in the inspected repository ([interview source](https://github.com/anatasof/NatPRD/blob/66e8d534082763456ebc0925963d4d18e50c6698/prompts/interview-questions.md#L9-L506)).
